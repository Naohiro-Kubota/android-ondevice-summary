# PoC・ADRゲート判定の補助

## 全体

PoCを実施したこと、PoCが技術的に合格したこと、ADRがAcceptedになったこと、MG-02a/02bで人間が全体を承認したことは別々の状態。GitHub Issueにはリンクを持たせる。

## 必ず失敗を停止要因として扱うP0検証

| 検証 | 注意点 |
|---|---|
| TV-001 / TV-015 | Pixel 9 Pro XLで日英要約・翻訳・FeatureStatusを確認。未対応端末への独断除外は禁止 |
| TV-005 / TV-013 | DNS rebinding、接続先と解決結果の一致、リダイレクト、安全でないIP範囲、サイズ制限 |
| TV-006 / TV-016 | Firebase 3製品、SDK自動イベントを含む禁止データの非送信 |
| TV-007 | 要約＋翻訳の共通排他、旧AI資源の安全な解放。解放未確認なら次AI開始不可 |
| TV-011 / TV-012 | 最前面喪失で中断、画面回転で継続、旧Intent再配送防止 |

※完全なTVレジストリと個々の優先度は必ず`docs/08-test-strategy.md`を参照する。上表の列挙のみでP0完了を判定しない。

## ADRレジストリ

ADR-001 HTTP/SSRF、002 本文抽出、003 ML Kit、004 AI排他制御、005 Firebase、006 ライフサイクル、007 CI・静的解析。

- 正本は`docs/adr/`の個別ADRとGitHub承認記録。
- 参考テンプレートは`docs/adr/ADR-TEMPLATE.md`。
- `Accepted`には採用対象とバージョン、承認者、承認日時、根拠リンクが必要。
- 承認のない`Accepted`表示は正当な承認として扱わず、差分の確認を求める。
