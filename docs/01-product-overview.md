# 01. プロダクト概要と意思決定

**版:** v2.7 / **状態:** 要求ベースライン確定・PoC未実施 / **作成:** 2026-10-10

## 1. 目的

Chromeで閲覧中の公開記事をAndroidの共有機能から受け取り、記事の主本文を取得・抽出し、端末内のAIで**日本語の箇条書き1〜3件**へ要約する。日本語記事は日本語で要約し、英語記事は英語で要約した内容を端末内で日本語翻訳する。日本国内向けのGoogle Play配布を計画する。

## 2. 想定利用者と価値

- Chromeでニュース・技術記事を読み、別アプリへ移動せず主要点を把握したい利用者。
- 記事全文をクラウドLLMへ渡さず、端末内で処理したい利用者。
- 必要に応じて要約をコピーし、元記事をブラウザで開き直したい利用者。

**MVPの中心シナリオ:** Chrome → 共有 → 本アプリ → URL検査 → HTML取得・本文抽出 → 言語判定 → モデル準備（必要なら承認・Wi-Fiダウンロード）→ オンデバイス要約 → 英語ならオンデバイス翻訳 → 結果表示。

## 3. 対象範囲

| 対象 | 方針 |
|---|---|
| プラットフォーム | Android。Kotlin、Jetpack Compose、Single Activity |
| 受け口 | ChromeのACTION_SENDで単一HTTP(S)記事URLを受信。通常起動では利用案内を表示 |
| 言語 | 日本語・英語の記事。日本語の結果を表示 |
| AI | ML Kit GenAI SummarizationとML Kit Translationが第一候補。端末内のみ |
| 端末 | Google公式のSummarization対応端末を対象とし、実行時に機能状態を確認 |
| 初期実機検証 | 保有端末のPixel 9 Pro XL **1台だけ**。他機種の実動作は未検証と明示 |
| 配信 | 日本向けGoogle Play。内部テスト→必要な公式手続き→一般公開 |
| 診断 | Firebase Analytics / Performance Monitoring / Crashlytics。厳格な情報制限 |
| 設計 | Manual DI、SessionCoordinator、単一appモジュール、Port/Adapter |

## 4. 明確な対象外

- クラウドLLMによる要約・翻訳、クラウドLLMへの自動フォールバック。
- Web記事の自前永続保存、要約履歴、データベース、ユーザーアカウント。
- URLの手入力、複数URL同時処理、ブラウザとしてのJavaScript実行・レンダリング。
- 専用のバックグラウンド要約タスク、共有以外からの定期自動取得。
- 元ページ全体テキストを抽出失敗時の無条件フォールバックとして使うこと。
- セッションをまたぐHTML・抽出本文・AI中間結果の再利用。
- Pixel 9 Pro XL以外での実機検証完了や、全対応端末での性能保証という表示。

## 5. 優先順位と判断原則

1. **安全性とプライバシー:** SSRF・リダイレクト対策、データの非永続化、診断用データの制限。MUSTの安全要件は点数評価によって緩和しない。
2. **正確性:** 主本文の取り違え・要約の重大な事実誤認を許容しない。確信できない場合は適切なERRで終了。
3. **最新共有優先:** 新たな共有は同じURLでも新セッション。旧セッションを直ちに無効化。古い結果は採用しない。
4. **AI資源の安全な直列化:** 要約と翻訳は共通ゲートで1件ずつ。旧処理の安全な解放確認前に新処理を始めない。
5. **小さな構造:** 単一Gradleモジュールで境界を明確にする。無目的にレイヤや抽象クラスを増やさない。
6. **人間による重要判断:** AIが調査・設計案・実装・テスト・文書更新を行い、人間がPoC/ADR/MG/Releaseを承認する。
