# 04. 非機能要件・非機能Acceptance Criteria

**版:** v2.7 / **状態:** 要求ベースライン確定。実測値の未承認を含む。

## 1. NFRレジストリ（全72件）

MUSTの安全・Privacy要件はスコアによる相殺を許さない。性能・品質の数値閾値は実機PoC後に人間が承認し、本ファイルの版を更新する。

| ID | 非機能要求 | 検証すべき性質（MUST） |
| --- | --- | --- |
| NFR-001 | 可用性 | 公式対応端末でも実行時機能状態を確認し利用不可を安全に案内 |
| NFR-002 | 信頼性 | 同一共有イベントを多重処理しない |
| NFR-003 | 正確性 | 別記事の本文を要約しない |
| NFR-004 | 事実整合性 | 元記事と矛盾する重要事実を抑制し重大誤認を評価 |
| NFR-005 | 部分要約の透明性 | 入力切り詰めを必ず表示 |
| NFR-006 | 入力エラーの可視性 | 不正URLや非対応言語は公開ERRに分類 |
| NFR-007 | UIの応答性 | 新共有やキャンセル時に画面を直ちに切り替える |
| NFR-008 | 非同期整合性 | 旧セッション結果が新セッションを汚染しない |
| NFR-009 | キャンセル安全性 | 可能な処理へキャンセルし、古い結果を無効化 |
| NFR-010 | 画面回転耐性 | 構成変更で二重起動しない |
| NFR-011 | プロセス復元抑止 | 旧記事・要約結果を復元しない |
| NFR-012 | トップフォアグラウンド限定 | 最前面喪失で記事セッションを終了 |
| NFR-013 | 処理時間計測 | 各段階と全体時間を計測できる |
| NFR-014 | 性能目標の実測決定 | P50/P95目標をPixel実測後に承認 |
| NFR-015 | メモリ使用 | 大容量HTML・AI入力を制限し不要参照を解放 |
| NFR-016 | 応答サイズ制限 | 圧縮前後のサイズ上限を設ける |
| NFR-017 | タイムアウト | 接続・読み込み・全体のタイムアウトを設ける |
| NFR-018 | リダイレクト上限 | 回数上限と危険転送遮断 |
| NFR-019 | SSRF耐性 | loopback/private/link-local/特殊IPを接続前に拒否 |
| NFR-020 | DNS安全性 | 解決結果と実際の接続先を安全に対応付ける |
| NFR-021 | HTTPS安全性 | TLSの検証とHTTPSからHTTPのダウングレード禁止 |
| NFR-022 | 入力データ保護 | リモートHTMLを信頼済み命令として扱わない |
| NFR-023 | ログの秘匿性 | Logcatや例外ログに記事本文・秘密URLを出さない |
| NFR-024 | キャッシュ無効化 | HTML・本文の独自ディスクキャッシュを作らない |
| NFR-025 | 暗黙永続化防止 | SavedStateHandle・rememberSaveableで記事本文を保存しない |
| NFR-026 | 失敗の耐性 | 診断失敗で本処理を失敗にしない |
| NFR-027 | 手動再試行のみ | HTTP429/5xxなどでも自動再試行しない |
| NFR-028 | 配信国 | 日本向けのPlayストア表示・言語を提供 |
| NFR-029 | アクセシビリティ | TalkBackと文字拡大に対応する |
| NFR-030 | UI規約 | 通常Activity画面・Material準拠の操作性を維持 |
| NFR-031 | テスト容易性 | 主要非同期依存をFakeに置換できる |
| NFR-032 | 依存方向 | Domain/ApplicationからSDK具体型へ直接依存しない |
| NFR-033 | 構造の簡潔性 | 単一appモジュールと必要なPortだけで構成 |

| NFR-037 | 診断禁止情報 | HTML、本文、AI入力・出力、認証値を送信禁止 |

| NFR-042 | プライバシー開示 | 収集範囲・用途・管理主体を案内する |
| NFR-043 | 適用法令確認 | 必要な同意がある場合収集前に同意を求める |
| NFR-044 | 第三者送信制御 | SDKが自動送信するデータをリリースゲートに含める |
| NFR-045 | エラー秘匿性 | 元例外メッセージ・causeを無検査でCrashlyticsへ渡さない |
| NFR-046 | 診断ホストの安全性 | ホストの正規化と機微情報検査を行う |
| NFR-047 | 安全なデフォルト | 診断URLを確認できなければ省略 |
| NFR-048 | リソース解放 | AIリソースを正しい順序で終了する |
| NFR-049 | 競合防止 | AI実行権をセッションの失効と区別して管理 |
| NFR-050 | モデル取得共有 | 同一モデル取得の重複起動を回避 |
| NFR-051 | 依存注入 | Composition Root・コンストラクタ注入をテスト可能にする |
| NFR-052 | AIゲートの安全性 | 旧推論解放確認前は新AI操作を許可しない |
| NFR-053 | モデル資産管理 | モデル状態のライフサイクルをセッションと分離 |
| NFR-054 | リリース構成の管理 | SDK/Gradle/OS/端末構成を記録する |
| NFR-055 | 診断データの共通検査 | TelemetryReporter手前で禁止値を排除 |
| NFR-056 | ホスト名限定 | URLパス・クエリ・フラグメント・userinfo等を送信しない |
| NFR-057 | 独自相関IDの非送信 | SessionId/ExecutionId/相関UUIDをFirebaseに送信しない |
| NFR-058 | GA4保持設定 | 対象ユーザー・イベントデータの設定を2か月とする |
| NFR-059 | 診断ホストFail Closed | 安全性を証明できないホストは除外 |
| NFR-060 | データ台帳 | 所有者・保持・削除・第三者送信を文書化する |
| NFR-061 | AI品質人間評価 | 自動評価に加えリリース候補で日英20件ずつレビュー |
| NFR-062 | PR CI | JVM Unit/ComponentとEmulator Smokeを必須にする |
| NFR-063 | 基準実機 | Pixel 9 Pro XL 1台で必須実機検証する |
| NFR-064 | RC Privacy | Release候補ごとにFirebase三製品の実動作を検証 |
| NFR-065 | 要件追跡 | MUST要件とテスト証跡を追跡可能にする |
| NFR-066 | 重大問題の遮断 | P0のSecurity/Privacy問題があればリリース不可 |
| NFR-067 | 検証証跡 | バージョン・実行環境・判定者・未実施を記録 |
| NFR-068 | Emulator全件 | 網羅的テストを定期・Release候補に必須とする |
| NFR-069 | AI変更追加評価 | 関連コード変更時に追加の品質評価を実施 |
| NFR-070 | 他機種リスク明示 | 他メーカー端末の実機動作は未検証と記録 |
| NFR-071 | 40記事記録 | 固定40記事の人間判定をビルドと結びつける |
| NFR-072 | 重大品質問題管理 | 未解決のCriticalをリリースの承認上可視化 |

## 3. データ・品質・実機の特別扱い

- **GA4保持は2か月:** GA4の対象ユーザー・イベントデータに適用。他Firebase製品や標準集計・外部エクスポートすべてに一律適用するものではない。
- **端末検証は1台:** Pixel 9 Pro XLのみ。Playの対象はGoogle公式Summarization対応端末だが、他機種は未実機検証として残存リスクに記載。
- **品質レビュー:** RCごとに日本語20記事＋英語20記事。重大な事実誤認は未解決ならRelease不可を原則とする。正確性評価は人間を必須とし、文字列完全一致のみで合否を決めない。
- **CI:** PRではJVMの全必須とEmulator Smoke、定期・RCではEmulator網羅的テスト。実SDKでのML Kit・Firebaseの検証はPixel実機とPoC。
- **RC Privacy:** Firebase三製品の明示的記録・自動収集をRelease候補ごとに検証。自動HTTP計測がURLパスを送信する、または安全を確認できない場合は無効化し、固定名のカスタムトレースで再評価。
- **データ破棄:** 管理可能な参照を終了時に解放する。OS/SDKメモリの物理的な即時消去までは保証しない。
